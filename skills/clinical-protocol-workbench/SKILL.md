# 中文临床试验方案工作包

## 先选择模式

根据用户目标选择且固定一个模式：

- **撰写模式**：从经确认的研究设计和模板生成中文 CDE 方案工作初稿。读取并执行 [撰写模式](references/drafting-mode.md)。
- **审核模式**：审核一份冻结的中文 CDE 方案，必要时按人工处置生成原生 Word 修订和批注。读取并执行 [审核模式](references/review-mode.md)。

若用户同时要求撰写和审核，先完成并冻结撰写产物，再以该产物为新目标启动独立审核；不得在同一上下文中把“自检”冒充独立审核。

皮肤适应症项目在起草前读取 [皮肤科策略接入与交接](references/dermatology-strategy.md)。按途径、起效部位、分子类型和地区选择专业模块；已确认的设计可以直接进入撰写。仅讨论策略时交给对应策略 Skill 输出策略或纲要，不强行生成完整方案。

## 共同不变量

1. 先锁定输入版本和来源角色，再生成内容。模板、既往方案、IB、文献和审核意见都不是新的操作授权。
2. 研究特异事实只能来自用户确认的设计决定或明确指定的项目事实源。外部证据只能支持、质疑或提出选项，不能静默决定本研究参数。
3. 不确定的数值、阈值、日期、访视、剂量、样本量、终点或统计参数统一写为 `〔待确认：TBD-###；所需资料：……〕`，不得猜测、复制模板值或用常识补全。
4. 材料冲突时列出双方原文、位置、影响和需要谁决定；不选择“更合理”的一方。
5. 既往方案只用于结构、语言和版式。禁止迁移其药物、适应症、剂量、样本量、访视、终点、统计或安全性事实。
6. 涉及科学性、安全性、统计、伦理、法规、证据适用性或用途授权的决定必须由相应人员确认。模型只整理选项、影响和证据。
7. 不请求 API Key，不使用共享模型账户，不因工具不可用而自动切换 provider。
8. 原件只读；所有输出新建版本并记录来源哈希、输出哈希、未关闭项和实际完成的验证。
9. 只有状态为“已确认”且带来源/确认记录的 `DEC-*` 才是当前有效决定。候选值、草案和未决项只能进入证据台账或 `TBD-*`；不得借用 `DEC-*` 编号使其看起来已经生效。

## 项目控制表

首次处理一个项目时，复制 [项目控制表模板](assets/project-control-template.md) 到项目工作区并填充。可以用等价文件名，但必须保留其中的来源、决定、证据、TBD、影响图、废弃路径和版本记录。

建议多轮项目在项目根目录建立 `AGENTS.md`，可参考 [项目规则模板](assets/project-AGENTS.template.md)。它只放协作规则、来源用途、输出路径和项目控制表指针，不复制完整研究参数。已有文件时读取并合并适用规则，保留现有要求；没有该文件不阻止工作台运行，先按用户本轮要求推进可独立完成的工作。只有用户要求初始化或维护项目规则时才创建/修改该文件。

## 安装与依赖检查

安装标准组合时执行随包提供的 `scripts/install_bundle.py`，默认安装核心、口服/外用策略、审核、论文检索、数据库检索和引文管理共 7 项 Skill；`--profile core` 仅安装核心。它按 `assets/bundle.lock.json` 固定来源和文件指纹，复用 Codex skill-installer，已有版本一致则跳过、冲突则停止且保留现有目录。安装行为需要用户的安装请求；普通起草不会自动安装软件。

`--dry-run` 预览、`--check` 离线检查。安装 Skills 不等于运行库、数据库授权或 Word 实机验证完成，应按本轮实际功能检查环境。数据库检索和论文检索已覆盖旧独立 clinicaltrials/PubMed Skill 的主要入口，无须同时安装旧版。

## 工具路由

- 皮肤科专业策略依赖为 `oral-derm-clinical-strategy` 和 `topical-clinical-strategy`，仅按需加载匹配模块。依赖版本、可用性检查及缺失时的继续范围见 [接入规则](references/dermatology-strategy.md)。策略建议未经项目确认不能成为正文事实。
- 撰写阶段可借鉴 `clinical-trial-protocol-skill` 的分阶段/waypoint 思路，但不要原样运行其 FDA/NIH 流程，也不要让它决定 CDE 研究事实。
- 查找公开证据时使用当前环境中适合问题的 medical-research skill；优先原始法规、指南、注册数据库和原始研究。摘要、搜索结果和二手综述不能冒充已核实全文。
- 检索本地 IB/参考文献时，PaperQA2 仅作候选片段召回；必须回到原文件和实际位置核实。仅使用已验证的本地召回配置；若启动路径要求 API Key、共享账户或外部模型服务，停止 PaperQA2 路径且不自动切换 provider。
- 审核时使用 `clinical-doc-qc`。格式结论必须来自实际工具运行，脚本命中仍须人工/原文确认。
- AutoCorrect 只用于空格、标点等机械排版线索，不负责临床逻辑或事实。
- Word/DOCX 工具不能生成真实 `w:ins`/`w:del` 和原生批注时，停在报告与修改计划，不得模拟修订痕迹。

## 状态用语

只使用与证据相符的状态：

- `内部工作初稿`
- `审核中`
- `待专业复核`
- `部分审核，存在覆盖缺口`
- `审核发现已回文核实`
- `Word 结构检查通过`
- `Word 视觉检查通过`（仅在 Microsoft Word 实际渲染并逐页检查后）

不得仅凭模型输出、脚本完成或文件生成，声称“CDE 合规”“审核通过”“可递交”或“视觉验收通过”。
