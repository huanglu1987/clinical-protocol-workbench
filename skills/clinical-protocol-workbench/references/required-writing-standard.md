# 每轮撰写与审核必读规范

用户指定的 `中文临床试验方案初稿撰写与自检规范_v2.md` 为两种模式的必读方法文件，内容版本 v2.3 / 2026-09-02。固定信息见 [版本清单](../assets/writing-standard.lock.json)。文件名中的 v2 不等于正文版本 v2.0。

## 执行时点与读取

1. 每轮开始实际撰写、完善方案、实质审核或形成受控修订计划前，先运行本 Skill 的 `scripts/check_writing_standard.py`，定位并核对本轮原文件。
2. 随后实际完整读取该文件全部 1,520 行，可以用 `--show --start 1 --end 250` 分段显示，连续读取至第 1,520 行；输出截断时补读缺口。脚本返回 matched、读取哈希、查看目录/摘要、此前读过或他人转述，均不等于本轮已读全文。
3. 完整阅读第零至第七部分及附录 A–D 后，按本轮模式应用对应章节。一次连续任务分章起草不需要每章重复全文；新的撰写/审核轮次、规范内容变化或失去可用全文上下文后，应重新完整读取。
4. 每个独立起草/审核执行上下文均自行完整读取同一冻结版本。主任务不能代替审核通道完成读取，也不能用主任务总结作为原文替代。
5. 在项目控制表第 11 节或等价执行记录中填写实际路径、版本、SHA-256、读取范围/缺口、本轮任务或通道及适用性处理。不要预填“已读完”。交付前再次核对哈希，内容变化则重新冻结并检查影响。

缺失、哈希不符或全文未读完时，明确标记必读规范未满足，不开始依赖该规范的正文生成或实质审核。仍可盘点文件、整理已提供资料和列出缺口。不得自动下载另一份同名文件、删减原文、重算固定哈希或以 clinical-doc-qc 替代这次全文阅读。用户明确改变本轮要求时按新的授权处理并记录差异。

## 规范与项目要求的衔接

- 该文件是经验方法规范，不是本项目事实源，也不是监管原文。所有案例中的药物、样本量、时间点、阈值、页数、命中率和改法只作示例；未经项目资料/确认支持不得迁入当前研究。
- 撰写时落实前置术语表、规则登记/章节归属、正例用途限定、数值出处与 TBD 管理；逐章用第 6.4 节自检，交付前按第 6.5 节逐项标明已执行、待人工、未覆盖或不适用。
- 审核时保留 A–L 分类和 L1/L2/L3 分工，用判别问句进行全文检查；词表是定位线索，不是穷举判据，更不能触发自动替换。每个独立通道均覆盖当前工作台规定的完整范围，分类分工不得造成总体覆盖缺口。
- J 类数值/事实及原文指定的 L3 项，智能体可抽取位置、整理证据与推算线索，但不得自报人工复核完成。原文中的“脚本召回率 100%”“全自动”等不构成本工具的能力证明，结果以实际工具覆盖和已完成检查为准。
- “每条规则唯一出处”用于维护同一有效决定及主要条款。模板或执行需要在摘要、正文、访视表中重复必要信息时，保留并做双向一致性核对；不得为了删重删掉必要执行内容。
- 原文“工作表/出处标注写完删除”仅指不混入最终正文；项目控制表、来源与批准记录仍应保留。不得清理既有 Word 修订/批注或质量记录。
- 字体、字号、引文体例、附录布局等应核对本项目已确认模板与适用要求；有冲突时列出原文、项目要求和影响，不擅改受控设计或监管原文。Word 域、页码和视觉结论依赖实际更新、渲染和逐页检查，不依据对 Word 默认行为的推测。

## 本地保存与安装

完整原文含内部案例，不随公开仓库或 Release 分发。用户已有使用权限的原文件可以通过 `check_writing_standard.py --install-source <原文件>` 原样复制到本机 Codex 配置目录下的 `clinical-protocol-workbench/standards/`；只写本地，已有不同内容不会覆盖。

默认依次查找该本机目录、当前项目根目录和用户桌面中的同名文件；也可以用 `--path` 明确指定本轮文件。找到第一份但版本不符时停止，不静默改用另一份。首次安装工作台后，若尚未提供该规范，应说明此项缺口；7 项 Skill 安装成功不代表必读规范已经可用。
