# 审核模式

仅在用户要求审核、QC 或受控修订一份中文 CDE 方案时读取。

## 1. 冻结审核范围

- 一个目标 DOCX 是唯一修订对象。
- IB、参考文献、指南和其他资料只作为证据。
- 记录所有文件版本、哈希、角色、审阅视图和无法解析的内容。
- 目标文件变化时建立新快照；不得把旧发现无条件套到新版本。

皮肤适应症可以按 [策略接入规则](dermatology-strategy.md) 为两路审核准备相同版本的疾病/剂型检查参考。策略推荐只作为待核查主张；每路直接核查冻结项目资料及原始依据。不要把起草者的自检结论作为检查答案，也不要把本轮审核过程中生成的新策略反馈给另一通道。依赖不可用时记录专业模块覆盖缺口，已授权的通用审核仍可继续。

## 2. 确定性检查

完整读取 `clinical-doc-qc` Skill；执行文本审核前按其要求读取方法论和语言参考。

必须实际运行其格式/结构检查脚本后，才能给出字体、字号、边距、编号或结构结论。脚本命中是调查线索，不是自动成立的问题；Word 页码必须在更新域并真实渲染后判断。

同时执行项目控制表中的术语、禁用语、TBD、废弃决定和信息用途扫描。关键词命中仍须结合语境确认。

## 3. 深度双通道

正式审核使用两个互不共享历史的新任务或执行上下文：

- 使用相同目标哈希、证据快照、规则版本和提示；
- 两路都做完整审核，不把一条仅限定为语言、另一条仅限定为医学；
- 结果完成前互不可见；
- 无法建立真正独立上下文时，明确标记为单通道，不宣称深度双通道完成。

为每一路保存审计记录：通道名、独立任务/上下文标识、目标与证据快照哈希、任务说明哈希、Skill/规则版本哈希、开始与完成时间、结果文件哈希，以及实际允许的资料和工具。仅产生两份文本或两份结果不同，不能证明执行上下文独立。

每路至少覆盖：研究设计与逻辑、受试者安全与伦理、中心可执行性、数值/统计依赖、法规与证据、语言与结构。多角色只是组织视角，不能替代数值和事实的人工核对。

## 4. 合并与回文核实

合并两路结果时保留来源和分歧。每条发现必须包含：

- 触发规则或概念；
- 精确位置和原文摘录；
- 冲突对照、依赖链或算式；
- 严重度及其依据；
- 证据状态和证据位置；
- A/B 通道来源；
- 回文核实结果；
- 建议动作和需确认角色。

审核报告不是权威来源。若其引用位置、算式或判据无法重现，应标记为误报或待复核，不得按其建议直接改文。

## 5. 人工处置

人工对每条发现选择：不采纳、仅报告、加批注、形成文字修改计划或待专业确认。

以下内容默认不能自动进入正文修改：设计、剂量、访视、终点、统计、阈值、单位、否定/条件/例外、安全性和法规结论。确定且不改变含义的机械文字问题，也必须先进入可审阅的修改计划。

## 6. Word 原生交付

只有冻结且获准的修改计划可以写入目标副本：

- 保留既有修订、批注、作者、日期和关系；
- 使用真正的 `w:ins`、`w:del` 和 Word 批注；
- 验证新增修订/批注 ID 唯一且作者、日期明确；批注范围锚点、引用、关系和内容类型完整；既有 ID、作者、日期、锚点、关系及现代批注部件（若原件存在）保持不变；
- 不覆盖输入，不接受旧修订，不清除旧批注；
- 不用红色文字、删除线或干净重写稿冒充审阅痕迹；
- 无法可靠定位或保全结构时，只保留在报告中。

仅出现 `w:ins`/`w:del` 标签不构成结构通过。交付前分别记录：OOXML 合法性与审阅关系检查、Microsoft Word 无修复提示地打开并实际渲染/逐页视觉检查、专业内容复核。前一层通过不能代替后一层。

最小交付：审核报告、带原生修订/批注的 DOCX 副本、未关闭项、输入输出哈希和验证限制。若 Word 能力不可用，则只交付审核报告和修改计划，并明确缺失的交付层级。
