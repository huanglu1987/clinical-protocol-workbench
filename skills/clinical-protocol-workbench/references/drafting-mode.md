# 撰写模式

仅在用户要求创建或完善中文 CDE 临床试验方案工作初稿时读取。

## 1. 确认输入角色

完整盘点用户提供的文件，记录哈希和以下角色：

| 角色 | 可以支持 | 不可以支持 |
| --- | --- | --- |
| 经确认项目事实 | 本研究已存在的真实资料 | 超出原文的推断 |
| 经确认设计决定 | 本研究当前有效的设计口径 | 冒充外部证据或监管要求 |
| 公司/CDE 模板 | 章节、样式、固定元数据结构 | 其他项目事实 |
| IB/研究报告 | 研究依据与已知风险 | 自动决定方案参数 |
| 法规/指南/文献 | 一般要求、设计依据和候选选项 | 填补本研究未决定数值 |
| 既往方案/正例 | 结构、文风和版式 | 药物、剂量、访视、终点等事实 |
| 策略 Skill 输出/候选 Synopsis | 设计选项、依据线索与待确认问题 | 直接成为已确认项目决定或原始证据 |

扫描件、未解析内容、摘要代替全文和无法定位的证据必须记录为覆盖缺口。

皮肤适应症按 [策略接入与交接](dermatology-strategy.md) 选择专业模块。先判断本次需要策略论证、纲要还是直接起草；已有经确认设计时复用有效确认记录，不重复要求批准，也不强制重做两条开发路径。

## 2. 先建立项目控制表

在正文前完成以下内容：

1. 来源清单；
2. 当前有效设计决定；
3. 术语、禁用语和信息用途规则；
4. 已核实外部事实、项目决定、证据缺口三分台账；
5. TBD 清单；
6. 章节依赖/变更影响图；
7. 已否决和已废弃路径。

当前有效设计决定至少包含值、单位、适用条件、来源或理由以及人工确认记录，并且状态必须为“已确认”。候选值、草案和未决项只进入证据台账或 TBD 清单，不分配会被下游当成有效口径的 `DEC-*`。登记册是当前口径，不取代原始证据。

调用专业模块时，在项目控制表第 10 节记录依赖版本和策略交接表。把每项候选建议的精确值/规则、依据与位置、适用条件、缺口和确认记录连接到 `DEC-*` 或 `TBD-*`；策略标题中的“推荐”或“正式策略判断”不是确认记录。

## 3. 人工确认门禁

先向用户展示会实质影响方案的未确认项。只有经用户或指定专业角色明确确认的决定才能进入正文。

缺少决定时仍可生成目录、章节问题清单或占位工作稿，但不得为了形成完整文档而补值。高风险歧义只问影响最大的一个问题，得到答案后再继续。

## 4. 建章节依赖图

从模板和已确认设计中识别：

- 摘要与正文的重复信息；
- 设计理由与操作章节；
- 入排标准与安全性/统计分析；
- 访视流程表与各检查章节；
- 给药、PK/PD、样本采集和统计参数；
- 参考文献编号与正文引用。

强依赖章节放在同一任务或顺序处理。优先并行资料抽取、证据核实和弱依赖章节；不要固定任务数，也不要把整份方案按页数机械切割。

## 5. 分段起草

每个起草任务必须得到同一版本的：

- 项目控制表；
- 模板章节；
- 本任务允许读取的来源；
- 相邻或强依赖章节的已冻结文本；
- 输出范围与禁止事项。

起草要求：

- 使用自然、科学、简洁的中文临床方案语言；
- 每个数值和实质性事实关联来源 ID 或设计决定 ID；
- 不扩大证据结论，不把团队决定包装成文献结论；
- 不删除或关闭 TBD；
- 不使用其他起草任务尚未确认的文本作为事实。
- 正文使用已确认的选定路径；保守/相对激进路径比较及未采纳理由留在项目控制记录。方案依法设计的多个治疗组不属于此处的未选定开发路径。

## 6. 主笔组装与复扫

组装后逐项核对：

1. 摘要、访视表、正文和附录的研究设计一致性；
2. 术语和缩写；
3. 章节/表格/参考文献交叉引用；
4. 数值依赖链、单位和算式；
5. 禁用语、内部工作语言和用途不符信息；
6. TBD 数量、位置和关闭状态；
7. 已废弃决定是否重新出现。

参数发生变化时，先从影响图列出所有相关位置，再形成变更计划；不得只修改当前发现的一处。

## 7. 生成与交接

- 新建方案输出干净 DOCX 工作初稿，不需要伪造修订历史。
- 在已有草稿上修改时，先冻结修改计划；正文实质修改需用户批准。
- 记录输入/输出哈希、实际验证、未执行检查和未关闭专业问题。
- 进入审核时，把初稿冻结为新的审核目标，并使用新的独立上下文；起草任务不得审核自己。

最小交付：工作初稿 DOCX、项目控制表、来源清单、TBD/冲突清单、限制说明。
