# 撰写与审核的每轮必读规范

从 v0.1.0-preview.5 起，每轮实际撰写、完善方案、审核和受控修订计划开始前，必须完整读取《中文临床试验方案初稿撰写与自检规范_v2.md》。其正文版本为 v2.3，日期为 2026-09-02，共 1,520 行；文件指纹在随包的 writing-standard.lock.json 中固定。

此前设计与个案验证曾使用该文档；本版将它接入日常执行的明确前置要求。不是只读摘要、目录或几条摘录，也不能因上一轮读过而直接跳过。每个独立起草或审核通道分别读同一冻结版本。一次连续任务分章起草不必每章再读全文。

## 首次在电脑上准备

原文件含内部项目案例，不随 GitHub 或 Release 分发。请通过有权使用的本地资料取得原文件；不需要把它上传到公开仓库。

把下列要求发给 Codex，并提供实际原文件路径：

```text
请使用工作台 scripts/check_writing_standard.py 的 --install-source 参数，
校验并在本机登记我提供的《中文临床试验方案初稿撰写与自检规范_v2.md》。
原文件路径：〔实际本地路径〕。
保留原件，已有不同版本不要覆盖。
```

脚本会将完全一致的副本保存在 Codex 配置目录的 `clinical-protocol-workbench/standards/` 下，位于 Skill 目录之外；升级核心 Skill 不会移走它。重复登记一致内容会复用，不一致则停止。

如果只为本轮使用某个路径，可调用 `--path <原文件>`。默认依次定位本机规范目录、项目根目录、桌面的同名文件。第一份文件不匹配时不会静默寻找别的版本。

## 每轮怎样执行

1. 运行 `check_writing_standard.py`，核对实际文件、版本和 SHA-256。
2. 实际完整读取全部正文和附录，可用 `--show --start 1 --end 250` 连续分段读至第 1,520 行；截断处补读。
3. 在项目控制表第 11 节记录本轮路径、版本、哈希、读取范围/缺口和各通道记录。
4. 按规范应用前置约束、逐章自检、A–L 分类及 L1–L3 分工。人工复核项保持待人工状态，不能由模型代签。
5. 交付前复核文件哈希，记录实际执行、未覆盖和适用性差异。

校验工具只证明取得了正确文件，不证明智能体理解或读完全文；其输出始终保留 `agent_read_complete: not_attested`。原文要求完整阅读属于工作流规则，不能宣称已有技术机制保证任何智能体必然遵从。

## 缺失和内容适用性

规范不可用、版本不符或未读完时，仍可盘点资料、整理来源和列出缺口；正文撰写及实质审核待补齐后继续。工作台不会自动改写规范、使用另一份同名文件或把 clinical-doc-qc 当作全文替代。

该规范提供方法，案例内容不成为研究事实。经验阈值、字体/引用建议和历史数据需要结合已确认模板及本项目要求使用；发生实质冲突时应记录并处置。L1“全自动”等表述不代表本工具已经实现全部检查。详细衔接边界见 [执行规则](../skills/clinical-protocol-workbench/references/required-writing-standard.md)。

AGENTS.md 仍是推荐但非必需的项目规则文件；这份自检规范是用户明确指定的必读方法文件，两者作用不同。
