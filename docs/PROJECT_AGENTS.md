# 撰写项目前是否需要 AGENTS.md

建议在长期协作或多轮起草前，在研究项目根目录建立 `AGENTS.md`。它不是运行 `clinical-protocol-workbench` 的必要条件：一次性任务可以直接在消息中说明规则；未建立该文件时，仍可盘点资料、建立项目控制表并起草可确认内容。

它的作用是让进入该项目的 Codex 任务持续知道资料如何使用、输出放在哪里、哪些决定需要确认。它不是临床方案、审批记录或研究事实库，也不是操作系统的只读/联网权限开关。其他智能体是否自动读取它，应按相应产品验证。

## 放在哪里、何时建立

```text
研究项目/
  AGENTS.md
  01_输入原件/
  02_外部依据/
  03_工作记录/
    项目控制表.md
  04_输出版本/
```

在 Codex 中打开这个研究项目目录，先检查该目录及适用的上级/子目录规则。项目已经有 `AGENTS.md` 时，应合并工作台需要的规则，保留现有要求；不要直接覆盖。不要在 Skill 安装目录写入真实研究项目规则，也不必为每一个子目录重复建立同样的文件。

先确定目录、来源用途和协作规则，再建立文件；完整的事实提取、哈希与设计决定随后登记到项目控制表。资料未齐全可以使用“待提供”，不必等所有研究参数确认才建立规则文件。

## 主要写什么

| 内容 | 建议写法 |
| --- | --- |
| 工作入口 | 使用工作台；本轮是策略、起草、完善还是审核，以实际任务要求为准 |
| 每轮必读规范 | 指定自检规范的本地路径、版本；撰写/审核及独立通道分别完整读取，控制表留痕 |
| 文件布局 | 原件、外部依据、工作记录、输出的实际路径 |
| 来源用途 | 哪份是事实源、设计来源或模板；详细列表指向控制表 |
| 设计确认 | 已确认决定的登记位置、真实确认记录位置；未决项留 TBD |
| 操作边界 | 原件只读、新建版本；变更须符合获准范围 |
| 写作要求 | 自然科学的中文、术语一致、保留必要监管和执行内容 |
| Word 交付 | 原生修订与批注要求，既有历史保留，实际验证层级 |
| 检索与资料外发 | 本轮已授权的检索范围；私有资料外发和云端操作的授权范围 |
| 版本与交接 | 输入输出哈希、控制表指针、未关闭事项、独立审核记录 |

不要把完整 IB、文献、方案正文、所有剂量/访视/统计数值粘进 `AGENTS.md`。这些内容会重复、容易过期，而且可能与当前确认版矛盾。也不要写“自动补齐全部参数”“默认接受所有修订”“任何资料均可上传”等超出实际授权的规则。

## 可直接使用的模板

工作台随安装提供 [项目 AGENTS 模板](../skills/clinical-protocol-workbench/assets/project-AGENTS.template.md)。复制到实际研究项目根目录并命名为 `AGENTS.md`，替换占位信息和路径。模板本身含有说明性占位，不是某个项目已经生效的规则。

可直接发给 Codex：

```text
请在当前研究项目目录启动 clinical-protocol-workbench 的方案撰写准备。
先读取适用的现有项目规则，盘点目录和我提供的资料用途。
使用工作台的 project-AGENTS.template.md 建立或合并项目根目录 AGENTS.md，
填入能够从本轮要求和现有文件确定的路径与规则；其余写为待提供。
已有同名文件请保留并合并，不覆盖现有要求。
同时使用项目控制表模板建立工作记录，研究事实及确认决定只登记在那里。
本轮允许公开检索的范围：〔填写〕。
输出目录：〔填写〕。不要补造研究参数或确认记录。
```

完成后查看路径是否真实、模板是否仅作模板、确认记录是否有效、检索与外发范围是否符合本次要求。长期稳定规则留在 `AGENTS.md`；本轮设计变化和待确认问题写在控制表，不需要每轮重复建立规则文件。
