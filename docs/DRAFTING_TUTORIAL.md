# 撰写模式详细教程

本文面向负责方案撰写和协调评审的医学经理。目标不是教医学经理编程，而是说明如何给智能体正确的资料、在什么节点作决定，以及怎样判断交付是否可信。

## 1. 先判断你属于哪一种撰写任务

| 当前状态 | 选择的入口 | 预期结果 |
| --- | --- | --- |
| 只有产品概况，研究设计尚未形成 | 策略论证 | 候选开发路径与需确认的设计问题，不直接写完整方案 |
| 已有初步设计，希望整理成可讨论的 Synopsis | 候选 Synopsis | 研究架构候选、依据、风险和 TBD，待团队确认 |
| 已有明确获确认的 Synopsis/设计决定 | 已确认设计直接起草 | 完整方案内部工作初稿 |
| 部分参数已定、部分未定，但需要先推进 | 占位工作稿 | 可确定章节 + 带编号 TBD，不猜缺失参数 |
| 已有一版草稿，需要完善 | 草稿完善 | 先盘点变更范围和授权，再产生新版本 |

“请撰写方案”不是对所有设计参数的默认授权。智能体会把已确认设计和未确认内容分开；医学经理负责提供或组织相应确认。

## 2. 开始前准备资料

### 2.1 最小资料包

至少准备：

- 产品名称/代号、剂型、给药途径、起效部位和分子类型；
- 适应症、拟开发地区和研究阶段；
- 当前可用的项目事实资料；
- 当前研究设计及其确认记录，若尚未确认则明确写“未确认”；
- 要采用的公司/CDE 方案模板；
- 输出要求及禁止事项。

### 2.2 推荐的完整资料包

| 资料 | 在本流程中的角色 | 常见误用 |
| --- | --- | --- |
| 获确认的 Synopsis/设计纪要 | 当前有效设计决定的主要来源 | 没有确认记录却当成最终设计 |
| IB 及更新记录 | 药理毒理、既往人体数据、已知/潜在风险 | 从非临床剂量直接推断临床剂量 |
| 临床药理/制剂/非临床报告 | 支持研究依据、风险和操作选择 | 把研究结果自动升级为本方案参数 |
| 公司/CDE 模板 | 章节、样式、固定元数据和标准段落 | 继承模板中的示例数值或其他项目内容 |
| 既往方案 | 结构、语言和版式参考 | 迁移剂量、终点、访视、样本量和安全性事实 |
| 法规、指南、全文文献 | 一般要求、设计依据、候选选项 | 用摘要或过期版本冒充现行原文 |
| 会议纪要/邮件/审批记录 | 证明谁在何时确认了什么 | “请继续”被解释为批准全部设计 |

### 2.3 文件组织

把输入原件和输出版本分开。原件只读，每轮输出使用新文件名。不要在发行仓库目录里存放真实项目资料。

建议告诉智能体每份文件的角色，例如：

```text
《IB_v3.0》：项目事实与风险依据；
《Synopsis_v0.7_医学统计已确认》：当前研究设计来源，确认记录见附件会议纪要；
《公司方案模板_2026》：只用于章节、样式和固定元数据；
《既往项目方案》：只用于语言和版式，禁止迁移任何研究参数；
《CDE指导原则》：外部依据，需核对版本和适用性。
```

### 2.4 是否先建立 AGENTS.md

建议多轮撰写项目在根目录先建立 `AGENTS.md`，一次性任务则可直接在消息中提供规则，不是必装或必建门槛。文件主要写资料用途、协作规则、实际目录、设计确认边界、输出与 Word 修订要求、检索权限，以及项目控制表的位置。剂量、样本量、访视、终点等研究事实统一放在控制表中。

已有 `AGENTS.md` 时先读取并合并，不能覆盖。具体放置位置、九类内容和可复制的启动提示见 [项目 AGENTS 使用说明](PROJECT_AGENTS.md)；随 Skill 安装的 [模板](../skills/clinical-protocol-workbench/assets/project-AGENTS.template.md) 可供建立项目文件使用。

## 3. 第一步：启动并锁定工作范围

每轮起草前先完整读取 [指定自检规范](REQUIRED_STANDARD.md)，记录版本、文件校验码及实际已读范围；缺少原文或未读完时先完成资料盘点，不开始正文。独立执行上下文分别读取，不能以之前读过或摘要替代。

在一个新的 Codex 任务中附上资料，发送：

```text
请使用 $clinical-protocol-workbench，进入撰写模式。
本轮目标：〔策略论证 / 候选 Synopsis / 已确认设计直接起草 / 占位工作稿 / 完善现有草稿〕。
适应症和地区：〔填写〕。
产品特征：〔口服/外用；局部或系统起效；小分子/其他；具体剂型〕。
请先完整盘点所有文件，记录版本并计算文件校验码（SHA-256），给每份资料分配来源角色和允许用途。
原件只读，所有输出新建到〔输出目录〕。
在我确认来源清单和关键设计状态前，不生成完整正文。
本轮允许的外部检索：〔允许并限定范围 / 不允许〕。
```

### 医学经理要检查什么

智能体返回的来源表中，每一份文件应有：文件名、版本/文件校验码、完整性、角色、允许用途和限制。重点检查：

- 有没有漏文件、把旧版当当前版或把扫描/OCR 当成完整准确文本；
- 有没有把模板、既往方案或外部研究列为“项目事实”；
- 有没有明确唯一的当前设计来源和确认记录；
- 冲突资料是否并列，而不是智能体自行选了“更合理”的版本。

确认方式应具体：

```text
确认采用你列出的来源清单 v1。补充修正：SRC-004 仅用于版式，不得支持任何研究事实；
SRC-002 是当前设计来源，确认范围只包括其第 2、3、5 节，统计附件尚未确认。
```

## 4. 第二步：建立项目控制表

来源范围确认后，让智能体复制并填写项目控制表：

```text
根据已确认的来源清单，使用工作包自带项目控制表模板建立 v0.1 工作记录。
请分别登记 SRC、当前有效 DEC、外部 EVD、未确认 PROP、TBD、HIST 和变更影响图。
没有真实确认记录的项目不要登记为 DEC。请先展示控制表摘要和需要我确认的最高风险问题。
```

### 如何看六类编号

- `SRC`：说明“这句话/这个数从哪里来，允许怎么用”；
- `DEC`：说明“本研究当前已经决定什么”；
- `PROP`：策略或团队提出但尚未生效的候选；
- `EVD`：支持/质疑一个主张的依据或证据缺口；
- `TBD`：还缺什么、影响哪里、由谁关闭；
- `HIST`：已经废弃的旧值，防止在长文组装时重新出现。

### 医学经理要检查什么

逐项查看 DEC，尤其是剂量、频次、疗程、样本量、随机比例、研究阶段、人群、主要终点、关键访视、安全观察期和统计原则。每一项应有精确值/规则、单位、适用条件、来源/理由和真实确认记录。

“看起来合理”“策略建议”“参考类似研究”都不能替代确认记录。

## 5. 第三步：需要时先做皮肤科策略

### 什么时候需要

- 研究设计尚未形成；
- 产品为口服或局部起效外用小分子，需要比较临床开发路径；
- 现有设计出现证据冲突，用户明确要求重新论证；
- 需要候选 Synopsis 供医学、统计、临床药理或法规讨论。

已有获确认设计且本轮只是起草时，不必强制重做策略。

### 启动提示词

```text
当前设计尚未确认。请在撰写模式中先完成皮肤科策略交接：
1. 根据给药途径、起效部位、分子类型和地区选择口服或外用策略 Skill；
2. 先运行依赖指纹核验，记录实际版本和读取的专业参考；
3. 输出候选策略和 Synopsis，列出依据、适用条件、保守/相对积极路径和证据缺口；
4. 所有建议登记为 PROP 或 TBD，不得写入 DEC 或完整方案正文；
5. 最后给出需要医学、统计、临床药理、药物警戒或法规分别确认的问题清单。
```

### 医学经理要检查什么

策略输出应清楚区分“法规/指南的一般要求”“公开先例”“项目内已有事实”“模型推断”和“团队要决定的参数”。确认某条建议时要注明精确范围：

```text
医学和统计共同确认 PROP-003 的研究总体设计、总样本量及 2:1 随机比例，适用于中国 II 期研究；
不确认其中的主要终点阈值和统计检验方法，分别保留为 TBD-012、TBD-013。
```

智能体随后应把已确认部分登记为 DEC，未确认部分继续留在 PROP/TBD。确认一个研究架构不等于关闭全部证据缺口。

## 6. 第四步：冻结“可起草设计包”

正文开始前，建议要求智能体输出一页“起草前门禁摘要”：

```text
请汇总本轮可进入正文的全部 DEC、尚未关闭的高风险 TBD、来源冲突和已废弃 HIST。
按摘要、研究设计、受试者、给药、访视与评估、PK/PD、安全性、统计和附录列出影响位置。
判断当前适合生成完整工作初稿还是只能生成占位工作稿，并说明理由。不要开始正文。
```

医学经理应确认：

- 所有核心设计都有明确状态；
- 没有候选建议被悄悄写成决定；
- 缺失参数的占位格式和责任角色清楚；
- 旧设计已进入 HIST，并列明不能复用；
- 形成方案所需但尚未关闭的医学/统计/执行问题已经可见。

如果信息不足，选择占位工作稿并不代表失败。它比自动补齐一个看似完整的方案更安全，也便于团队定向补资料。

## 7. 第五步：建立章节依赖图和起草计划

发送：

```text
基于冻结的项目控制表和公司模板，建立章节依赖图与分段起草计划。
把重复使用同一决定的摘要、正文、访视流程表、给药、PK/PD、统计和附录关联起来。
强依赖章节应同组或顺序起草；资料抽取和弱依赖章节可以并行。
列出每一组允许读取的来源、使用的 DEC/TBD、相邻冻结文本和验收点。
```

不要按页数机械分割。常见强依赖关系包括：

- 研究目的—终点—估计目标/统计分析；
- 入排标准—风险控制—禁止/限制用药—退出；
- 剂量与给药—依从性—药品管理—PK 采样；
- 访视流程表—各检查章节—时间窗—提前退出；
- 样本量—随机分配—分层—分析集—表格合计。

## 8. 第六步：分段起草

推荐的先后顺序不是固定模板，但通常可以这样组织：

1. 方案元数据、术语、缩写和目录骨架；
2. 研究背景与依据；
3. 目的、终点和总体设计；
4. 研究人群、入排标准和退出/终止；
5. 试验干预、随机盲法、依从性和合并用药；
6. 访视、疗效/安全性/PK/PD 评估和样本管理；
7. 不良事件、风险控制和紧急处置；
8. 统计、数据、质量、伦理及行政章节；
9. 摘要、访视流程表、附录和参考文献；
10. 全文组装与一致性复扫。

每组可以使用下面的提示：

```text
起草〔章节名称〕。只使用项目控制表 v〔版本〕中允许的 SRC 和已确认 DEC；
可以引用的来源为〔列出〕，相邻冻结文本为〔列出〕。
尚未确认的内容保留原有 TBD 编号，格式为“〔待确认：TBD-###；所需资料：……〕”。
不得从模板、既往方案、外部研究或其他未冻结章节迁移研究参数。
使用自然、科学、简洁的中文临床方案语言。
输出本章节正文、使用的 DEC/SRC 对照、未关闭项及与其他章节的依赖。
```

### 医学经理逐段检查

- 每个数值是否能回到 DEC 或项目事实来源；
- 风险描述是否与 IB/已知资料一致且没有扩大结论；
- 是否遗漏条件、例外、提前退出和异常场景；
- TBD 是否仍保留并能定位责任人；
- 文风是否自然、专业，而不是把法规或英文模板机械翻译；
- 有无把其他章节的草稿当成新的事实来源。

## 9. 第七步：主笔组装和全文复扫

所有分段冻结后发送：

```text
请作为主笔组装所有冻结章节，保持公司模板样式，并完成全文一致性复扫：
1. 摘要、正文、访视流程表和附录中的研究设计；
2. 术语、缩写、单位、编号和交叉引用；
3. 剂量、频次、疗程、样本量、分配数和访视时间的数值依赖链；
4. 入排、安全性、统计和执行规则中的条件及例外；
5. TBD 数量、位置和状态；
6. 已废弃值是否重新出现；
7. 参考文献编号和正文引用。
先返回复扫报告；发现实质性冲突时不要自行选值，列出原文、影响和需确认角色。
```

### 参数变更怎么处理

不要说“把 24 例改成 30 例”就直接全文替换。正确做法是：

```text
已确认变更：DEC-006 总样本量由〔旧值〕变为〔新值〕，确认记录见〔位置〕。
请先根据影响图列出摘要、设计、样本量、随机分组、受试者流程、表格、图示、附录和版本记录中
所有需更新或重新核对的位置。只输出变更计划，不修改正文；待我批准计划后再生成新版本。
```

设计数值改变后，原值进入 HIST；统计依据若未同步确认，原有 TBD 不能自动关闭。

## 10. 第八步：生成 DOCX 工作初稿

复扫问题处置后，发送：

```text
我批准按冻结的组装稿和处置记录生成 DOCX 内部工作初稿。
请新建文件，不覆盖任何输入；保留所有未关闭 TBD，不伪造修订历史。
交付时同时提供项目控制表、来源清单、TBD/冲突清单、输入输出文件校验码（SHA-256）、
实际完成的结构/格式/视觉检查，以及明确未执行的检查。
```

新起草的方案通常交付干净 DOCX，不需要制造红线。若是在已有草稿上做实质修改，应先冻结修改计划并取得批准，再决定是否需要审阅副本。

## 11. 医学经理的交付验收表

### 文件与版本

- [ ] 输入原件未被覆盖，输出为新版本；
- [ ] 输入、控制表、正文和输出文件校验码可对应；
- [ ] 文件名、版本、日期和页眉页脚口径一致；
- [ ] 本轮实际检查和未执行检查分别列出。

### 设计与事实

- [ ] 摘要、正文、访视表和附录中的设计一致；
- [ ] 所有实质性参数都可追到已确认 DEC 或项目事实；
- [ ] PROP、外部先例和模板参数没有进入正文；
- [ ] 每个 TBD 有位置、所需资料、责任角色和状态；
- [ ] 已废弃决定没有复活。

### 临床与执行

- [ ] 人群、终点、给药、访视、安全性和统计逻辑已由相应专业角色复核；
- [ ] 提前退出、方案偏离、异常结果、紧急揭盲等条件场景可执行；
- [ ] 中心操作、样本处理、药品管理和数据流程没有只写原则而缺算法/时限/责任；
- [ ] 外部证据适用于对应地区、产品、途径和人群。

### 文档层

- [ ] 编号、表图、交叉引用、术语、缩写和参考文献一致；
- [ ] 页码/目录等涉及 Word 域的结论来自实际更新与渲染；
- [ ] “已生成 DOCX”没有被写成“审核通过”“CDE 合规”或“可递交”。

## 12. 一条可复制的完整起草提示词

```text
请使用 $clinical-protocol-workbench，进入撰写模式，为〔适应症/阶段/地区〕项目形成中文 CDE 方案内部工作初稿。

产品特征：〔给药途径、局部/系统起效、分子类型、具体剂型〕。
本轮入口：〔策略论证 / 候选 Synopsis / 已确认设计直接起草 / 占位工作稿 / 完善草稿〕。
输入资料及角色：
- 〔文件1〕：项目事实，允许用途〔填写〕；
- 〔文件2〕：当前设计来源，确认记录〔位置〕；
- 〔文件3〕：公司模板，只用于结构与样式；
- 〔文件4〕：既往方案，只用于语言和版式；
- 〔文件5〕：外部证据，需核对适用性。

请先锁定全部输入版本/文件校验码，建立来源清单和项目控制表。只有带真实确认记录的项目进入 DEC；
候选建议进入 PROP，证据进入 EVD，未确认内容进入 TBD，废弃值进入 HIST。
如设计未定且产品适用，请核验并调用匹配的口服或外用皮肤科策略 Skill；策略输出不直接进入正文。
先展示起草前门禁摘要、关键 TBD 和章节依赖图，等我确认后再分段起草。
每段只使用获准来源和已确认 DEC，缺失参数保留带编号 TBD，不得从模板、旧方案或公开先例补值。
```

## 13. 常见问题

**资料不全还能写吗？** 可以完成来源盘点、目录、可确定章节和占位工作稿。不能为了“完整”猜剂量、终点、样本量、访视或统计参数。

**策略 Skill 给了推荐，为什么还要确认？** 策略建议是带依据的候选，不是申办方设计决定。医学经理需要组织适当角色明确确认其内容和适用范围。

**已有批准的 Synopsis，是否还要重做策略？** 不必。登记可定位的确认记录后直接起草；只有出现未决设计、证据冲突或明确要求重新论证时才回到策略阶段。

**能否一次让智能体写完？** 技术上可以，但长文更容易发生跨章节漂移。推荐先冻结来源和设计包，再按强依赖关系分段，最后统一组装。

**初稿生成后就是审核完成吗？** 不是。起草自检用于组装质量控制；正式审核应冻结初稿并在新的独立任务中使用审核模式。
