# 审核模式详细教程

每轮实质审核前，主任务及每个独立通道均须完整读取 [指定自检规范](REQUIRED_STANDARD.md)，记录同一版本、哈希和各自实际读取范围。它提供 A–L 分类与 L1–L3 方法，不能作为本项目事实来源；缺失或未读完时先补齐，不以其他 Skill 替代这次全文阅读。

本文面向负责方案审核、问题处置和版本交付的医学经理。审核模式默认只读：先查清问题，再由人决定是否修改。

## 1. 适用场景

- 对一份中文 CDE 方案进行完整医学、逻辑、执行、统计、法规、语言和结构审核；
- 对方案与 IB、ICF、SAP 或其他资料做一致性核对；
- 定稿前只做格式和文字校对；
- 对已确认问题形成修改计划；
- 在逐项批准后生成带真实 Word 修订和批注的新副本。

若只是快速格式+文字校对，要明确缩小范围；没有做深度逻辑检查时必须在报告开头声明。

## 2. 准备审核包

指定一个唯一目标方案，并说明审阅视图：当前显示文本、接受全部修订后的文本，还是保留修订状态下的版本。其他资料只能作为证据，不能一起成为“默认可修改对象”。

建议提供：

- 唯一目标 DOCX；
- IB、确认的设计/Synopsis、公司模板和适用法规/指南；
- 若做跨文件核查，明确哪个文件是唯一事实基准；
- 已知重点问题，但说明“重点”是叠加还是唯一范围；
- 本轮只审核还是也准备修改计划；
- 是否允许联网核实现行证据；
- 是否要求两个独立通道。

## 3. 第一步：冻结范围

```text
请使用 $clinical-protocol-workbench，进入审核模式。
唯一审核目标为〔文件名〕；其他附件均为证据，不得修改。
本轮为〔深度审核 / 格式+文字校对〕；重点关注〔填写〕，这些重点〔是叠加项 / 是本轮唯一范围〕。
先记录所有文件的版本、SHA-256、角色、完整性和审阅视图，报告无法解析的内容。
原件只读，本轮先只输出审核报告和修改计划，不写入 Word。
```

医学经理核对目标哈希和来源角色后再继续。目标文件变化时必须建立新快照，旧报告不能无条件套用。

## 4. 第二步：确定性格式与结构检查

审核模式会读取 `clinical-doc-qc`，并实际运行其格式/结构检查工具。需要确认：

- 中文 CDE 资料使用对应规则集；
- 字体、字号、行距、边距等结论确实来自工具，不是智能体“看文字”推测；
- 表图编号、交叉引用、缩写定义和残留修订/批注得到检查；
- DOCX 的目录缓存页码没有被直接判错；应更新 Word 域并导出 PDF 后判断。

工具的错误/警告不能原样当最终报告。每条命中需结合位置、原文和实际意义解释，误报应剔除或标为待复核。

## 5. 第三步：深度文本审核

```text
请完整通读目标方案并自行建立 8–15 项关键操作概念清单；我点名的重点是叠加项，不是范围上限。
逐项检查研究设计与逻辑、受试者安全与伦理、中心可执行性、数值/统计依赖、法规与证据、语言与结构。
多文件时分别核对一致性、主文件到派生文件的覆盖性、派生文件到主文件的依据性。
数值问题给出完整算式；语义矛盾给出两处可定位原文；条件和例外条款代入真实执行场景。
未命中或沉默不能直接写成一致，无法核实的项标为待人工复核。
```

概念清单应来自全文，而不是只查剂量、样本量等关键词。常见概念包括：入组/随机规则、剂量调整、漏服/中断、访视窗、提前退出、研究终止、紧急揭盲、AE/SAE 处置、妊娠、救援治疗、方案偏离、样本处理、数据截止和分析集。

## 6. 第四步：正式材料采用独立双通道

正式审核建议在两个互不共享历史的新任务中使用完全相同的冻结材料和提示。两个通道都做完整审核，不能让一个只看语言、另一个只看医学。

为每个通道保存：任务标识、目标/证据哈希、提示哈希、Skill/规则版本、开始/结束时间、允许资料和工具、结果文件哈希。

如果当前环境不能建立两个真正独立的执行上下文，报告应写“单通道”或“部分审核”，不能仅生成两份文本就声称完成双通道。

可复制给两个新任务的统一提示：

```text
使用 $clinical-protocol-workbench 审核冻结目标〔文件名与 SHA-256〕。
证据快照为〔文件清单与 SHA-256〕，不得读取其他项目资料。
这是独立完整审核；不要参考另一审核者结论。
实际运行 clinical-doc-qc 的格式/结构检查，并按方法论做全文概念、语义、数值、条件场景和证据审核。
每条发现给出触发规则、严重度依据、精确位置、原文/冲突原文或算式、证据状态、建议动作及确认角色。
只输出报告，不修改文件。
```

## 7. 第五步：合并与回文核实

两路完成后，合并者应保留 A/B 来源和分歧，逐条重新打开原文和证据。报告不是权威来源；引用位置、计算或规则不能复现的发现标为误报或待复核。

最终问题表至少包括：

| 字段 | 要求 |
| --- | --- |
| 触发规则 | 概念清单、语义比对、数值链、条件场景、格式工具等 |
| 严重度 | 高/中/低，并说明科学性、安全性、合规或执行影响 |
| 位置与原文 | 可让第二审阅者快速找到并推翻/确认 |
| 对照或算式 | 冲突原文、依赖链、计算结果和文档所载值 |
| 证据状态 | 已核实全文、摘要线索、冲突、缺失或不适用 |
| 通道来源 | A、B 或两者；保留分歧 |
| 回文核实 | 成立、误报、待人工复核 |
| 建议处置 | 不采纳、仅报告、批注、修改计划、待专业确认 |
| 确认角色 | 医学、统计、药物警戒、法规、运营等 |

## 8. 第六步：医学经理逐条处置

医学经理对每条发现明确选择：

- 不采纳，并记录理由；
- 仅保留在审核报告；
- 在 Word 中加批注，不改正文；
- 形成具体文字修改计划；
- 待医学/统计/药物警戒/法规/运营确认。

设计、剂量、访视、终点、统计、阈值、单位、否定、条件、例外、安全性和法规结论默认不能自动改正文。即使是机械文字问题，也先进入可审阅的修改计划。

批准应指向唯一版本和条目：

```text
批准《修改计划 v0.3》，SHA-256 为〔填写〕。
批准 F-002、F-005 进行文字替换；F-009 仅加批注；F-011 待统计确认，不进入本轮 DOCX。
批准范围仅限上述动作，其他发现不处理。原件不得覆盖，既有修订和批注必须保留。
```

## 9. 第七步：生成 Word 原生审阅副本

只有已冻结并获准的计划可以写入新副本。要求：

- 使用真实 Word 插入/删除修订和原生批注；
- 保留既有修订、批注、作者、日期和审阅关系；
- 不接受旧修订、不清除旧批注、不修改未批准条目；
- 无法精确定位或可靠保全结构的条目留在报告中；
- 原件哈希在前后保持不变。

可复制提示：

```text
请使用 $clinical-protocol-workbench，按已批准的《修改计划〔版本与SHA-256〕》生成审阅副本。
批准动作仅限〔条目及动作〕。使用真实 w:ins/w:del 和原生 Word 批注；保留全部既有审阅历史。
不得覆盖原件、接受旧修订、清除旧批注或扩大修改范围。
不能可靠处理的条目留在报告。
交付前分别完成并报告 OOXML/关系检查、Microsoft Word 无修复打开和对象枚举、更新域、
导出含标记 PDF、逐页视觉检查以及待专业复核项。未执行的层级明确写未执行。
```

## 10. 第八步：分层验收

### 结构层

- [ ] 新增修订/批注 ID 唯一；
- [ ] 批注范围、引用、关系和内容类型完整；
- [ ] 既有修订、批注及现代评论部件未被破坏；
- [ ] 未触及包部件按计划保持；
- [ ] 原件未改变，输出哈希已记录。

### Microsoft Word 实机层

- [ ] 无修复提示打开指定输出副本；
- [ ] 修订、批注数量和作者符合计划；
- [ ] 更新域时没有产生额外修订或错误；
- [ ] 导出的是含修订标记的 PDF；
- [ ] 文档关闭时不回写验证副本。

### 逐页视觉层

- [ ] 每页实际查看，不用抽页代替全量；
- [ ] 修订气泡、批注、表格、页眉页脚、目录、分页和交叉引用可见且无截断；
- [ ] 记录页数、PDF 哈希和发现；
- [ ] “自动导出成功”没有被称为“视觉检查通过”。

### 专业内容层

- [ ] 每条文字变化与批准计划一致；
- [ ] 医学、统计、安全性和法规问题由相应角色关闭；
- [ ] 未关闭项继续保留；
- [ ] 技术检查通过没有被解释为专业批准或可递交。

## 11. 快速校对和深度审核的区别

| 项目 | 格式+文字校对 | 深度审核 |
| --- | --- | --- |
| 格式/结构工具 | 做 | 做 |
| 错别字、术语、单位 | 做 | 做 |
| 概念清单 | 不要求 | 必须 |
| 语义矛盾 | 不做 | 做 |
| 数值依赖链 | 不做 | 做 |
| 条件/例外场景 | 不做 | 做 |
| 多文件内容关系 | 不做 | 做 |
| 报告声明 | 必须说明未做深度审核 | 列明完整覆盖和缺口 |

“重点审核”不等于“只审核”。只有医学经理明确说“只查这些项目”，才缩小范围，并必须把未覆盖内容写在报告开头。

## 12. 常见问题

**脚本没有报错是否等于方案没有问题？** 不是。脚本擅长可确定的格式/结构线索，语义矛盾、执行条件、证据适用性和数值依赖仍需全文审核。

**两次在同一个对话里运行是否算双通道？** 不算。它们共享历史，后一轮会受到前一轮结论影响。

**审核发现能否自动修改？** 默认不能。先回文核实，再由医学经理逐条处置并批准唯一修改计划。

**没有 Microsoft Word 能否交付审阅稿？** 可以交审核报告和修改计划；若工具能生成 DOCX 也只能报告实际完成层级，不能声称 Word 实机或视觉检查通过。

**审核通过是否等于可递交？** 工作包不使用这种自动结论。是否递交需要所有专业未关闭项、版本控制和组织审批按实际流程完成。
