# 临床文档本地 worker：实验审阅模块

实验模块，不是通用真实临床文件编辑器。Python 3.12；依赖 lxml 6.1.1。生成函数没有网络、模型或文件系统写入入口；测试使用合成 DOCX，部分验证测试从合成构建产物读取。完整准备步骤见 [开发说明](../docs/DEVELOPMENT.md)，先生成测试样例再运行下面命令。

```sh
PYTHONPATH=worker python3 -m unittest discover -s worker/tests -v
```

当前实现：

- 有资源上限的 OPC 容器读取，检查重复项、路径、XML 实体、宏、签名、外部关系、保护等。
- 源文件/段落/计划哈希和精确字符锚点；拒绝模糊查找替换及过期计划。
- 只在普通正文或简单单元格中的单一纯文本 run 内操作。每段最多一处；字段、链接、书签、旧修订内部及复杂结构不写入。
- 两个窄机械规则：重复中文逗号删除；两侧是汉字的 ASCII 逗号改中文逗号。另有预定义的“灼热→烧灼感”精确术语替换；其存在不构成其他项目的用语授权，仍需实际项目逐项确认。规则名称、严重度和用户确认都不能授权任意文本替换。
- 原生 `w:ins` / `w:del` / `w:delText`，保留 run 属性；原生经典批注内容、范围、引用、关系和内容类型。
- 盘点保留已有简单插入/删除和经典批注；未触及包部件逐字节保留；撤销新增修订后检查源语义恢复。

当前此目录回归共 67 项：58 项 DOCX/审阅验证，9 项 workbench 策略依赖完整性验证；两类结果不能混为临床质量证据。开发阶段已对 macOS Word 的合成“简单修订 + 经典批注”子集完成实际打开、对象枚举、含标记 PDF 导出和逐页检查；该历史结果不自动适用于新文件。现代评论、移动/属性修订和复杂结构仍整体阻断；未进行完整 XSD 验证，也未验证 Windows。生成函数自身只返回 `spike_subset_passed`、`word_visual_status=not_performed`，不能从一次生成调用中推断 Word 实机或视觉结论。

`user_confirmed` 和冻结计划来自未来可信主进程，本模块不提供身份认证。当前无 IPC 或模型可调用入口；不得把从模型 JSON 直接填入的字段当成人工授权。完整任务权限、封存和新文件原子落盘由下一批集成实现。
